# 금손한의원 정보전달형 단일 글 구조

이 문서는 금손한의원 정보전달형 글의 **유일한 구조 기준**이다. 다른 문서·자산·스크립트·레퍼런스는 글의 순서나 대체 골격을 정의할 수 없다. 충돌하는 과거 구조는 절충하지 않고 삭제한다.

## 고정 순서

```text
제목
→ 공감: 독자가 실제로 떠올릴 질문 인용구 2개 이상
→ 가치입증: 금손한의원 소개 표
→ 해결책 예고: 3분 투자와 구체적인 이득 또는 피할 손실
→ 제목의 숫자와 일치하는 번호 소제목 n개
→ 글 전체 정리
→ CTA
```

위 순서는 모든 정보전달형 글에서 바꾸지 않는다. 주제에 따라 바뀌는 것은 질문, 해결책, 소제목의 답과 설명, 정리와 CTA의 내용뿐이다.

## 1. 제목

- 스킬이 제안하는 제목은 독자에게 알려 줄 서로 다른 답의 개수 `n`을 숫자로 표시한다.
- 사용자가 확정한 제목은 글자 하나 바꾸지 않는다.
- 제목이 약속한 숫자와 번호 소제목 개수는 정확히 같아야 한다.
- 같은 뜻을 억지로 나눠 숫자를 채우지 않는다. 서로 다른 답이 부족하면 제목을 만들거나 확정하지 않는다.

## 2. 공감 인용구

- 제목 바로 다음에는 독자가 검색하면서 실제로 떠올릴 법한 질문을 인용구로 둔다.
- 질문은 2개 이상 쓴다. 보통 2~3개면 충분하지만, 개수보다 서로 다른 걱정이나 생활 장면을 담는 것이 중요하다.
- 증상명과 추상어를 조립하지 않는다. 환자가 실제로 입으로 묻는 단어를 쓴다.
- 질문에 답하거나 원장을 소개하는 문장을 인용구 앞에 두지 않는다.

예시 형식:

```text
> 살을 뺐는데 조금만 먹어도 다시 찌는 이유가 뭘까요?
> 다이어트가 끝난 뒤에는 어떻게 먹어야 요요가 덜 올까요?
```

예시는 형식만 보여 준다. 다른 글에 문장을 복사하지 않는다.

## 3. 금손한의원 소개 표

- 공감 인용구 바로 다음에는 `금손한의원 소개` 표를 정확히 한 번 둔다.
- 행의 문구와 순서는 `assets/goldhand-value-proof-library.json`을 단일 기준으로 사용한다.
- 표 밖에서 같은 경력과 강점을 다시 길게 자랑하지 않는다.
- 다른 업체의 경력·수치·성과는 가져오지 않는다.
- 평문 승인 전에는 표의 내용을 아래처럼 행 단위 텍스트로 보여 주고, 승인 뒤 같은 문구를 실제 표로 조립한다.

```text
[금손한의원 소개]
11년차 한의사 · 2016년 개원
...
```

## 4. 해결책 예고와 독자 보상

- 소개 표 다음에는 이 글을 짧게 읽으면 무엇을 알게 되는지 한 문단으로 말한다.
- `3분`이라는 낮은 읽기 부담과, 독자가 얻을 이득 또는 피할 손실을 구체적으로 연결한다.
- `좋은 정보를 드리겠습니다`처럼 막연하게 쓰지 않는다.
- 의료 결과를 보장하지 않는다. 증상이 낫는다고 장담하지 말고, 원인·구분 기준·다음 행동을 이해하게 된다는 정보상의 보상을 약속한다.
- `고민을 단번에 해결할 거라고 자신합니다`를 모든 글에 복사하지 않는다. 주제에 맞게 자연스러운 한국어로 새로 쓴다.

예시 원리:

```text
3분만 읽어보셔도 왜 다시 찌는지, 무엇부터 바꿔야 하는지 분명히 알 수 있습니다.
```

## 5. 번호 소제목 n개

- 제목 숫자와 같은 수의 번호 소제목을 정확히 둔다.
- 각 소제목은 주제명이 아니라 제목에 대한 직접적인 답이어야 한다.
- `1.`부터 빠짐없이 연속해서 번호를 붙인다.
- 각 소제목 안에서는 상황, 이유, 주의할 점, 환자가 할 일을 해당 답을 이해하기 좋은 순서로 자연스럽게 설명한다.
- 소제목 내부에 별도의 고정 공식을 만들지 않는다. 사례, Q&A, 위험 신호, 진료 설명은 필요한 소제목 안에서만 사용하며 독립된 새 글 구조로 추가하지 않는다.
- 제목 숫자 밖의 추가 핵심 답이나 번호 없는 주요 소제목을 만들지 않는다.

## 6. 글 전체 정리

- 번호 소제목에서 설명한 답을 짧게 한 번 정리한다.
- 본문 전체를 문장만 바꿔 반복하지 않는다.
- 독자가 지금 기억해야 할 선택이나 행동을 분명히 남긴다.
- 정리와 CTA는 아래 두 역할 조합 중 하나로 닫는다. 두 조합은 새로운 글 구조가 아니라 같은 `정리 → CTA` 블록이 해야 할 일을 정한 기준이다. 적힌 문구를 그대로 복사하는 템플릿이 아니다.

### 마무리 역할 A: 도움이 되었길 바란다는 인사 → 감사 → 직접 확인 권유

- 정리 문단은 방금 설명한 구체적인 증상이나 행동을 자연스럽게 회수하고, 독자가 이해하는 데 도움이 되었기를 바란다고 말한다. `오늘 말씀드린`은 쓸 수 있는 연결 중 하나일 뿐 필수 문구가 아니다.
- 같은 정리 문단에서 읽어 준 데 대한 감사의 뜻을 전한다. `긴 글 읽어주셔서 진심으로 감사드립니다`, `여기까지 함께해 주셔서 고맙습니다` 같은 문장은 방향을 보여 주는 예시일 뿐이다. 다른 글에 그대로 돌려 쓰지 않는다.
- CTA 문단은 감사 뒤에 이 글이 일반적인 설명이라는 경계를 자연스럽게 밝힌다. `다만`, `이 글은`, `오늘 말씀드린 내용은`도 문맥에 맞을 때만 쓴다.
- 이어서 어떤 불편이 계속될 때 직접 진료를 받아 무엇을 확인해 보아야 하는지 주제에 맞게 말한다.
- `오늘 말씀드린 정보가 도움이 되셨길 바랍니다`처럼 내용이 비어 있는 문장을 모든 글에 복사하지 않는다. `두 가지 요요 습관`, `계단을 내려갈 때 생기는 무릎 통증`처럼 방금 설명한 내용을 구체적으로 회수한다.

### 마무리 역할 B: n가지 내용의 이득 또는 피할 손실 → 다음 행동 → 감사

- 정리 문단은 제목에서 설명한 n가지를 참고하거나 기억했을 때 독자가 얻을 수 있는 구체적인 이득이나 피할 수 있는 실수를 말한다. `오늘 말씀드린 n가지만 참고하셔도`는 역할을 보여 주는 예시일 뿐, 필수 시작 문구가 아니다.
- `n가지`는 제목에서 약속한 답 개수와 같아야 한다. `2가지`를 `두 가지`처럼 자연스럽게 풀어 써도 된다.
- CTA 문단은 불편이 계속되거나 혼자 판단하기 어려운 경우 직접 진료에서 무엇을 확인할 수 있는지 말한다.
- CTA 문단의 마지막은 읽어 준 데 대한 감사의 뜻으로 닫을 수 있다. 같은 뜻이라도 글의 길이, 주제, 앞 문장에 맞게 새로 쓴다.

두 역할 모두 감사의 뜻은 한 번이면 충분하다. 같은 감사 문장을 여러 글에 반복하지 말고, 위치에 맞지 않는 `여기까지`나 `끝까지`도 억지로 넣지 않는다. 사진이나 외부 레퍼런스에 나온 다른 병원의 경력, 지역, 연락처, 문의량, 대기 시간, 치료 주장, 완성 문장은 가져오지 않는다.

## 7. CTA

- 정리 바로 다음에 부담을 낮춘 CTA를 둔다.
- 무조건 방문하라고 압박하지 않는다.
- 혼자 판단하기 어렵거나 불편이 계속되는 경우 어떤 내용을 진료에서 함께 확인할 수 있는지 말한다.
- 역할 A라면 일반 정보라는 경계를 밝힌 뒤 직접 진료나 진단으로 현재 상태를 확인해 보길 권한다. 역할 B라면 주제에 맞는 다음 행동을 제안한 뒤 감사 인사로 끝낸다.
- 마지막 두 블록에는 `금손한의원`, 지역 한의원 키워드, `저희 한의원`을 넣지 않는다. `금손한의원에서 진료를 받아보세요`처럼 특정 병원으로 독자를 끌어당기지 않는다.
- 예약, 문의, 전화, 대표번호, 찾아오는 길, 내원 유도를 넣지 않는다. `불편이 계속된다면 직접 진료를 받아보시는 것을 권해드립니다`처럼 독자가 의료기관을 선택할 여지를 남긴다.
- CTA가 글의 마지막 블록이다. 자동으로 FAQ, 함께 읽을 글, 별도 교훈, 또 다른 요약, 지도, 운영정보 표를 뒤에 붙이지 않는다. 사용자가 별도로 요청한 연락 정보는 CTA 안에만 넣는다.

## 다른 구조는 사용하지 않는다

위 고정 순서 외의 다른 글 배열은 정의하거나 선택하지 않는다.

## 레퍼런스에서 배운 역할

아래 4편은 문장과 업체 사실을 가져오는 자료가 아니라, 사용자가 정한 각 블록의 역할을 확인하는 구조 참고 자료다.

- https://blog.naver.com/gyumiji0307/223487738117
- https://blog.naver.com/helptaxking_/223702773986
- https://blog.naver.com/rededu1143/223438237392
- https://blog.naver.com/jinsoso7000/223454347466

레퍼런스에서는 사용자가 지정한 각 블록의 역할만 배운다. 글의 순서는 이 문서의 고정 순서가 절대 기준이다.

- `jinsoso7000` 글은 설명 뒤에 독자의 실제 일정과 필요 조건을 다시 묻고, 도움을 받을 수 없는 경우까지 밝힌 뒤 다음 행동을 제안한다. 전화번호와 업체 유도는 가져오지 않고 `독자 상황 회수 → 조건 → 다음 행동`만 배운다.
- `rededu1143` 글은 감사 문구 없이 핵심 원칙을 짧게 연속해 결론을 만든다. 감사 한 문장이 아니라 `마지막에 무엇을 기억시킬지`가 먼저라는 점만 배운다.
- `helptaxking_` 글은 독자의 마지막 망설임에 직접 답하고 여러 곳을 비교해 보라는 선택 기준을 먼저 준다. 업체 자신감과 상담 유도는 가져오지 않고 `마지막 질문에 답하기 → 독자에게 선택권 돌려주기`만 배운다.
- `gyumiji0307` 글은 n가지 기준을 다시 회수한 뒤 특정 업체에 꼭 갈 필요는 없다고 부담을 낮추고, 선택적 안내와 감사로 닫는다. 금손 글에서는 업체명과 연락 유도를 모두 빼고 `n가지 회수 → 부담 낮추기 → 중립적인 다음 행동 → 감사`만 배운다.

- 공감은 독자가 실제로 묻는 질문으로 시작한다.
- 가치입증은 긴 자기소개보다 짧은 표가 빠르다.
- 해결책 예고는 짧은 읽기 시간과 구체적인 보상을 연결한다.
- 소제목은 제목의 숫자와 맞는 직접 답이다.
- 마무리는 오늘 설명한 내용을 구체적으로 회수한 뒤, 독자가 얻을 이득이나 직접 확인이 필요한 경우를 말하고 부담을 낮춘 CTA로 이어진다.
- 네 글의 감사 문장과 업체 CTA를 복사하지 않는다. 배울 것은 `핵심 회수 → 독자에게 남는 이득 → 선택권을 남긴 다음 행동`이라는 역할이다.
- 한 글은 핵심 원칙만으로 닫고, 다른 글은 마지막 망설임에 답하며, 또 다른 글은 특정 업체에 갈 필요가 없다고 압박을 낮춘다. 금손 글에서는 이 차이를 살리되 병원명 없는 중립적인 진료 권유로 바꾼다.
