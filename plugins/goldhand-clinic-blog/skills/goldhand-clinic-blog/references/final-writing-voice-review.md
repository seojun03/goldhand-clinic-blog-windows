# writing-voice 최종 재청취 검수

이 단계는 금손한의원 글의 **마지막 글쓰기 검수**다. 레퍼런스와 금손 사실로 내용·순서·의료 경계·제목 약속을 모두 확정하고 SEO용 정확 키워드까지 자연스럽게 넣은 다음 실행한다. 이후에는 모바일 줄바꿈, 강조, 이미지, 표, 링크, HTML 같은 제작 조립만 한다.

이 검수는 [direct-clinic-voice-generation-prompt.md](direct-clinic-voice-generation-prompt.md)와 [v113-approved-writing-style.md](v113-approved-writing-style.md)를 초안 전에 적용한 글을 확인하는 마지막 안전망이다. 자기검수 기록을 채우는 것만으로 자연스러운 글이 되지 않는다. 사용자 확정 v1.13 호흡과 충돌하는 문장이 있으면 체크 항목이 모두 true여도 실패로 돌린다.

최종 문장마다 실제 주어·목적어·서술어·평이한 뜻과 문맥 속 역할을 확인한다. 미리 정한 문장 형태나 `clinicUtteranceForm` 라벨로 문장을 제한하지 않는다.

이 문서는 `writing-voice` 스킬을 금손한의원 글에 적용한 휴대형 계약이다. 다른 사용자 환경에 별도 스킬 파일이 없어도 같은 검수 기준이 플러그인에 남는다. `writing-voice`가 함께 제공된 환경에서는 해당 스킬을 최종 문장 검수자로 사용하고, 이 문서가 금손 글에서 바꾸면 안 되는 범위를 정한다.

## 역할을 섞지 않는다

- 금손한의원 플러그인: 무엇을 넣고 어떤 순서로 말할지 결정한다.
- 선택 레퍼런스: 제목·도입·흐름·전환·마무리의 독자 심리를 결정한다.
- 금손 사실·의학 경계: 말할 수 있는 사실과 확신의 강도를 결정한다.
- `writing-voice`: 이미 선택된 내용을 박준희 원장의 말로 더 잘 들리게 한다.

`writing-voice` 검수는 문단을 추가·삭제·이동하거나, 근거·사례·감정·경험·의도를 새로 만들지 않는다. 자연스럽게 보이게 하려고 의료 경계를 약하게 하거나 단정을 세게 만들지도 않는다.

## 검수 전 동결값

아래 항목을 내부적으로 잠근다.

1. 확정 제목과 메인키워드
2. `orderedContentAtoms`와 `flowBeats`의 순서
3. 금손 사실, 일반 의학 정보, 예외와 안전 경계
4. 선택한 제목·도입·마무리 장치와 주제별 보상
5. 독자 고민, 소제목, 문단, 표, 이미지 앵커의 순서
6. 고정 가치입증 6행, 운영정보, `clinic-info` 이후 추가 요소 0개

최종 재청취 뒤에도 이 값은 같아야 한다. 이 값을 바꿔야만 해결되는 문제라면 문장 검수가 아니라 앞선 금손 작성 단계의 실패다. 해당 단계로 되돌려 고친 뒤 최종 재청취를 처음부터 다시 한다.

## 전체를 말하는 속도로 다시 듣기

문장 하나씩 금지어를 찾는 방식으로 끝내지 않는다. 제목부터 마무리까지 한 사람에게 설명하듯 실제 말하는 속도로 읽는다.

다음 지점을 표시한다.

- 글 첫머리의 질문 2~3개가 인사보다 먼저 나오지 않거나, 두 질문이 모두 `증상명 때문에 …나요?`처럼 같은 문법 틀과 호흡으로 찍혀 나온 곳
- `홍조 때문에 …나요?` 다음에 `불면 때문에 …나요?`처럼 증상 이름만 바꾼 평행 질문, 한 질문 안에서 `피로와 가라앉은 기분도 이어지나요?`처럼 증상 목록을 추상 서술어로 묶은 곳
- 의미 없이 문단을 잇는 상투적인 연결 문장
- 모든 문단이 같은 길이와 같은 종결로 눌린 곳
- 문장이 짧아 보이도록 뜻을 삭제했거나, 반대로 서로 다른 주체와 시점을 한 문장에 묶어 첫 번에 이해하기 어려운 곳
- 질문과 지시만 문맥 없이 줄줄이 이어져 문진표나 생활수칙 목록처럼 들리는 곳
- 번호 답을 후기 버전식 문단·문장 제한으로 잘라 원인·생활 장면·진료 판단을 충분히 설명하지 못한 곳
- 같은 질문이나 안전 행동을 되짚었지만 독자의 이해나 안전을 위한 실제 역할 없이 동일 문장을 복사한 곳
- 고정 인사 뒤 실제 결론 대신 `이럴 때 볼 것은 두 가지·첫째·둘째를 살펴보겠습니다`처럼 글 진행을 안내하는 곳
- 마지막 번호 답 뒤에 치료 뒤 확인·응급 안내·참지 말라는 소제목을 여러 개 붙여 제목 숫자 밖의 숨은 항목을 만드는 곳
- 마무리를 `판단이 회복을 좌우합니다·다시 걷기 위한 출발입니다·처음의 선택이 중요합니다` 같은 추상 표어로 쓰거나 `진료받아 보셔도 됩니다`로 행동을 흐리는 곳
- `그 답을 들은 뒤·질문이 달라집니다·두 질문부터 해야 하죠`로 실제 판단 대신 문진 절차를 말하거나 `필요하지 않다면 권하지 않습니다`로 병원 태도를 방어하는 곳
- 직접 요청문이든 제3자 진료 설명이든 누가 움직이고 누가 묻거나 보는지 모호한 곳
- `그런데·그래서·다시·따로·이어`가 실제 대조·원인·반복 없이 문장 연결 장식으로 들어간 곳
- 첫 진료 장면에서 아직 오지 않은 다음 날의 증상을 이미 묻거나 치료 전후 시점을 거꾸로 쓴 곳
- 결과지는 가져올 수 있지만 사진을 `들고 진료받다`고 하는 등 사물과 행동이 실제 입말에서 어울리지 않는 곳
- 구체적인 환자 장면보다 블로그다운 요약이나 교훈으로 시선이 옮겨 간 곳
- 원장의 솔직한 확신·유보·주의가 무난한 공문체로 평평해진 곳
- 근거 없는 비유, 여운, 권위, 친절함을 덧칠한 곳
- 원래 살아 있던 짧은 단정, 질문, 반복, 호흡을 generic한 좋은 글로 정상화한 곳
- `어느 불편이 하루를 가장 많이 흔드는지 알면 설명도 이어집니다`처럼 추상 명사와 작문용 서술어만으로 앞뒤를 연결해, 실제로 무엇을 묻고 무엇이 달라지는지 들리지 않는 곳
- `차도 움직인다는 이유로`, `오른쪽부터 아픈지`, `약 이름보다 아픈 때부터`, `같은 더부룩함처럼 보여도`, `식후 포만감으로 설명합니다`, `어디가 더 아픈지도 진찰합니다`, `경고할 증상`, `발목을 시험하지 마세요`처럼 단어는 쉬워도 실제 대화에서 만들지 않는 결합
- `잠·식사·카페인·진통제를 묻습니다`처럼 무엇을 묻는지 생략한 명사 목록, `치료 전과 후를 서로 비교합니다`처럼 문법상 불필요한 부사, `계속 토하는 때`처럼 조건을 억지로 시간 명사로 만든 표현
- `광주 ○○ 한의원 진료를 받으러 오셨다면`, `광주 ○○ 한의원 진료에서도`, `광주 ○○ 한의원에 오실 때는`, `저희 금손한의원은 광주 ○○ 한의원 진료에서`처럼 정확 키워드를 넣기 위해 만든 SEO 문장
- 정확 키워드를 앞 문장에 따로 쓰고 다음 문장을 `저희 금손한의원에서는`으로 시작해 사용자 승인 문자열을 둘로 쪼갠 곳
- `저희 광주 ○○ 한의원에서는`처럼 정확 키워드 뒤의 실제 병원명 `금손한의원`을 생략해 키워드가 상호처럼 들리는 문장
- `환자가 짚은 아픈 곳과 체중이 실리는 무릎이 같은지`처럼 종류가 다른 두 대상을 비교하는 문장
- `저는 고개와 허리를 직접 움직여 본 뒤`처럼 원장이 자기 몸을 움직이는 것으로도 읽히는 문장, 한 문장 중간에 환자와 원장의 행동 주체가 바뀌는 문장
- `몇 시간 뒤 무엇이 아프기 시작했는지`, `어느 곳이 아픈지`처럼 이미 알고 있는 신체 부위를 부정대명사로 다시 흐리는 문장
- `한의 치료를 적용할지`, `치료를 시행할지`처럼 진료실 말보다 행정문에 가까운 서술어
- `붓기가 커지다`, `두통이 덜 오다`, `근력과 균형이 돌아오다`, `발목이나 다리에 힘이 들어오다`, `진료에서 말씀하다`, `무리하지 않는 운동`, `병원 검사가 급하지 않다`, `먹고 언제 더부룩한지`처럼 쉬운 단어지만 실제 입말에서는 서로 잘 붙지 않는 결합
- `무릎이 언제, 어디에서 아픈지`, `발목과 골반을 진찰해서`처럼 외부 장소와 몸의 위치를 섞거나 실제 진찰 동작을 넓은 신체 부위 이름으로 대신한 문장
- `버티는 것보다 멈춰야 할 때를 알아야 합니다`처럼 지금 멈출 행동 대신 교훈을 만들어 낸 마무리
- 출근·운전·운동 세 항목 뒤에 `이 두 행동`이라고 쓰거나, `각각·두 가지·세 가지`가 앞에서 실제로 센 항목 수와 맞지 않는 문장
- `다친 시각과 걸을 수 있는 거리를 들은 뒤`, `병원 진료부터 말씀드립니다`, `식사 뒤 언제부터 답답한지와 속쓰림이 생기는지 묻습니다`처럼 종류가 다른 목적어나 질문을 한 서술어와 `-는지와`에 묶은 문장
- `탄산음료 뒤에`, `냄새 뒤에`처럼 먹고 마시고 맡는 행동을 생략한 문장과 `끼니를 거렸는지` 같은 기본 오탈자
- `사고 직후 괜찮다고 몸에 이상이 없다고`처럼 같은 인용 조사, `식사 뒤 바로 … 바로`처럼 같은 부사를 가까이 반복해 입말 호흡이 끊기는 문장
- `통증이 생기는 부위를 봅니다`, `어느 동작에서 아픈지도 직접 보겠습니다`, `복숭아뼈 주변을 눌러 아픈 곳을 확인합니다`, `목 뒤쪽이 당기는지 봅니다`, `트림이나 구역감이 생기는지도 듣습니다`처럼 환자만 느끼는 감각을 눈으로 보거나 원장이 확인한다고 쓰고 문진을 생략한 문장
- `이 질문을 듣고 저는`, `다친 날의 통증만 듣고`처럼 질문을 듣는 사람과 답을 듣는 사람을 뒤집거나 실제 질문을 생략한 문장
- `어느 부위에 왜 치료하는지`, `어떤 치료가 왜 필요한지`, `침으로 충분한지`, `침 치료만 권해도 된다면`, `치료 이름부터`, `발목과 골반은 제가 직접 보겠습니다`처럼 실제로 놓고·누르고·움직여 보게 하고·권하는 진료 행동을 넓은 명사나 허가 표현으로 숨긴 문장
- `치료할 곳을 고릅니다·한의 치료를 시작할 수 있는지 설명합니다·침 치료만 설명합니다·침이나 추나요법이 필요하다면 왜 쓰는지 설명합니다`처럼 부위·진찰 결과·치료 판단 없이 행정만 보고하는 문장
- `통증이 생기는 부위와 목이 돌아가는 정도를 봅니다`처럼 환자에게 물을 감각과 원장이 볼 동작을 한 서술어에 묶은 문장
- `같은 말을 해서는 안 됩니다`, `식사량과 시작 시간`, `반복되기 전에 먹은 음식`처럼 무엇이 같은지·무엇이 시작되는지·어떤 증상 전에 먹었는지 독자가 보충해야 하는 문장
- 실제로 안 아팠던 환자에게 `안 아픈 척 넘기지 마세요`라고 해 통증을 일부러 숨긴 사람처럼 만든 문장
- `보호하세요·대세요`라고 지시하다가 같은 문단에서 `감고·올립니다`로 청자와 종결을 바꾼 문장
- `붓기를 보고, 아픈 곳을 확인하며, 한 발로 서게 해 봅니다`처럼 문진·관찰·촉진을 한 문장에 세 가지 이상 넣은 검수 보고서식 문장
- `골절이나 구조 손상`, `역류성 식도염이 있는지 진료받다`처럼 포함 관계나 목적어·서술어가 맞지 않는 병렬·진료 문장
- `위에서 음식이 천천히 내려가다`, `위가 조금만 늘어나다`처럼 환자가 말할 수 있는 증상 대신 장기 작동을 번역해 쓴 문장
- `허벅지 근육이 무릎을 잡는 힘`, `무릎이 안쪽으로 무너지다`, `힘이 크면`, `한 시간 안에 빠르게 부었다면`처럼 신체를 의인화하거나 원인과 관찰 기준을 생략한 문장
- `허벅지에 힘이 들어가야 합니다`, `같은 쪽인지가 첫째입니다`, `첫째는 … 것입니다`, `두 답을 들은 뒤`처럼 눈으로 보이는 동작 대신 추상적인 힘이나 계산식 문장으로 번호 답을 만든 곳
- `사고가 난 시각과 통증이 시작된 날부터 묻습니다`, `잠·끼니·커피 가운데 언제 더부룩했는지`처럼 서로 다른 시간 단위나 생활 습관을 하나의 질문에 억지로 묶은 곳
- `병원 진료부터 권합니다`, `영상검사를 받을 수 있는 병원 진료`, `검사받을 병원으로`, `다른 병원 진료를 권합니다`, `말하고 치료합니다`처럼 조사와 명사를 겹쳐 실제 안내·설명·치료 순서를 숨긴 곳
- `영상검사가 통증까지 대신 말해 주지 않습니다`, `증상을 가립니다`처럼 검사나 증상을 사람처럼 말해 실제 질문과 안전 지시를 숨긴 곳
- `침 치료가 필요한지 진찰합니다`, `어느 부위에 침을 놓는지와 그 이유`처럼 치료 여부를 되풀이하거나 실제 부위를 문서식 묶음으로 다시 숨긴 곳
- `오후에 시작해 몇 시간 갔는지`, `진통제는 약 이름만큼`, `열이 나면서 목이 뻣뻣한 때`, `어느 쪽에서 목 뒤가 당기는지`처럼 번역투 시간·비교·방향 결합이 남은 곳
- `무릎이 아픈 곳과 몸이 기우는 쪽을 말씀해 주세요`처럼 원장이 볼 움직임을 환자의 답으로 바꾸거나, `술을 마시거나 달리지도 마세요`처럼 서로 다른 지시를 한 어미에 묶은 곳
- `X-ray 검사를 받을 수 있는 병원으로`, `침이 필요한 곳과 이유`처럼 실제 검사 행동과 치료 부위를 가능·장소 명사로 돌려 말한 곳
- `병원에서 받은 검사 결과도 가져오세요`처럼 기존 검사 이력을 전제하거나, `정신이 흐려지거나 두통이 심해질 때`처럼 서로 다른 응급 조건을 한 문장에 묶은 곳
- `환자의 답을 들은 뒤 편두통이 의심되는지 살핍니다`, `잠을 못 잔 날도 빼놓지 않습니다`, `빠뜨리시면 안 됩니다`처럼 다음 질문이나 환자가 말할 내용을 생략한 곳
- `물을 거의 마시지 않는 일도 피하세요`, `모든 음식을 한꺼번에 끊게 하지 않습니다`처럼 부정 명사구나 사역문으로 실제 환자 지시를 돌려 말한 곳
- `발목이 굽혀지고 골반이 기우는가`, `먹은 음식보다 먹는 방법까지`, `소화제보다 병원 검사가 먼저인 때`처럼 조사·명사로 끝나 원장의 말이나 환자의 행동이 없는 소제목
- 한 문장에 질문 세 가지 이상을 쉼표로 붙인 문진표, 제목의 세 가지 답을 마지막 한 문장에 다시 욱여넣은 요약
- 마무리에서 `첫 번째입니다·두 번째입니다·세 번째입니다`로 번호 답을 다시 복창하거나 앞의 질문·응급 안내·진찰·치료를 다시 요구한 곳
- 한 문장에 질문을 두 개 이하로 줄였더라도 다음 문장들을 모두 `묻습니다·말씀해 주세요`로 쪼개 문진표를 그대로 유지한 곳
- 직접 요청문과 제3자 진료 설명 중 어느 방식을 쓰든 행동 주체와 관찰 주체가 문자 그대로 맞지 않는 곳
- `그래서 다시 묻습니다·이어 묻습니다`처럼 실제 원인·반복 없이 연결어로 질문 수를 늘린 곳
- `치료받은 날뿐 아니라 다음 날도 덜 아픈지 묻습니다`처럼 현재 진료와 다음 방문의 시간축을 섞은 곳
- `사진을 들고 진료받으세요·침을 놓는다고 설명합니다`처럼 실제 행동 대신 어색한 결합이나 설명 행위만 남긴 곳
- `같은 소화불량이라고 한 가지 처방을 만능처럼 드리지 않는 이유입니다`처럼 이유 절만 결론으로 남고 원장의 실제 행동이 뒤따르지 않는 문장
- `현재 상태·실제 변화·치료 순서·통증 단계·수면 모습·생활 움직임`처럼 시간·동작·증상 대신 추상 명사 묶음으로 설명한 곳
- `몸 상태를 넘기다·일상을 밀다·잠이 흐트러지다·허리가 허용하다·더 많은 이야기를 해 주다`처럼 실제 사람이 진료실에서 쓰지 않는 작문용 결합
- `함께 살펴보겠습니다·말씀드리겠습니다·순서의 문제입니다`처럼 실제 결론이나 진료 행동 대신 블로그 진행과 여운을 말하는 도입·마무리

문법적으로 더 매끈한 문장이 있다는 이유만으로 고치지 않는다. 현재 문장이 독자 관계, 확신의 강도, 강조점, 말의 호흡을 더 정확히 보여 준다면 그대로 둔다.

박준희 원장의 구체적인 낱말, 조금 비정형적인 말 순서, 짧은 반복이나 옆길이 실제 강조·유보·관계를 보여 주면 보존한다. 몇 개의 대화형 어미만 남기고 전체 자세를 generic한 친절한 전문가 말투로 바꾸면 실패다.

## 수정 방식

문제가 있는 보이는 문장만 국소적으로 고친다. 각 수정에는 `더 자연스럽게`가 아니라 표현이 수행할 일을 적는다.

좋은 설명의 예:

- 환자가 어느 동작에서 아픈지 바로 떠올리도록 추상 명사를 생활 장면으로 바꿈
- 지나치게 공손한 유보가 안전 지시를 흐려 직접적인 주의 문장으로 되돌림
- 같은 길이의 세 문장이 이어져 핵심 판단이 묻히므로 짧은 단정과 설명의 호흡을 되살림
- 원장의 확신보다 블로그 요약이 앞서 있던 문장을 독자 질문에 바로 답하도록 고침

수정이 필요하지 않으면 `no-change-needed`로 기록하고 문장을 억지로 바꾸지 않는다.

국소 수정처럼 보여도 원장의 확신, 독자와의 관계, 감정의 무게를 실질적으로 바꾸는 선택이라면 해당 문장을 임의로 바꾸지 않는다. 앞선 금손 작성 단계로 돌아가 같은 사실과 구조 안에서 다시 쓰고, 그래도 해결되지 않으면 완성본으로 표시하지 않는다.

## 수정 뒤 전체 재청취

부분 수정이 끝나면 고친 문장만 보지 말고 제목부터 다시 읽는다. 다음을 모두 확인한다.

- 첫 보이는 문장은 서로 다른 생활 장면을 묻는 질문 2~3개이고, 그 다음 문단이 고정 인사인가
- 첫 질문 묶음을 한꺼번에 소리 내어 읽었을 때 증상명만 바뀐 동일 문장 틀이나 같은 종결 호흡이 반복되지 않는가
- 새 연결어가 앞뒤 문단의 리듬을 다시 평평하게 만들지 않았는가
- 독자의 고민보다 작성자의 설명 기술이 더 눈에 띄지 않는가
- 금손 특유의 구체적인 말과 솔직한 경계가 남아 있는가
- 사실·확신의 강도·의료 경계가 전과 같은가
- 내용 원자와 흐름 비트가 같은 순서로 모두 남아 있는가
- 키워드와 제목 약속이 그대로인가
- 금손의 진료를 설명하는 문장에 주체·실제 행동·이유가 보이는가
- 추상 포장어를 검색해 실제 시간·동작·증상으로 풀지 않은 문장을 모두 고쳤는가
- 완곡하거나 추상적인 결론을 사용자가 확정한 직접적인 표현 강도로 되돌렸는가
- `manualReview.directVoiceSentenceAudit`의 문장·검색어·등장 순서가 최종 본문과 정확히 일치하는가
- 정확 키워드 문장이 `저희 {정확 메인키워드} 금손한의원에서는` 구조를 지키며 뒤에 실제 질문이나 진찰을 바로 말하는가
- 정확 키워드와 `저희 금손한의원에서는`을 두 문장으로 분리하지 않았으며 입력 키워드로 만든 승인 문자열이 최종 평문에 실제로 존재하는가
- `같은지·비교합니다` 양쪽의 대상이 같은 종류이고, 움직이거나 말하거나 보는 사람이 문장 중간에 바뀌지 않는가
- 각 문장을 가장 쉬운 말로 바꿨을 때 원문에 없던 주체·부위·동작을 보충하지 않아도 뜻이 그대로 통하는가
- 각 주어·목적어와 서술어가 사전적으로만 가능한 조합이 아니라 환자 앞에서 실제로 함께 쓰는 한국어인가
- 나열 뒤의 수사·지시어가 실제 항목 수와 맞고, 시간·거리·음식·증상마다 맞는 서술어를 따로 썼는가
- 통증·저림·당김·메스꺼움·구역감은 몸을 누른 뒤에도 환자에게 물었고, 뒤꿈치 들림·발목 흔들림·골반 기울임처럼 눈으로 볼 수 있는 동작만 보았는가
- `묻다·듣다·보다·설명하다·권하다·치료하다`에 실제 주체와 구체 목적어가 붙었으며 치료 행동을 `어느 부위에 왜 치료·어떤 치료가 왜 필요·침 치료만 권해도 된다`로 줄이지 않았는가
- 같은 조사·부사·명사가 가까이 반복되지 않고, `치료 이름·같은 말·시작 시간` 같은 넓은 명사가 실제 내용을 다시 덮지 않았는가
- `발목이나 다리에 힘이 들어오다`, `안 아픈 척`, `골절이나 구조 손상`처럼 뜻을 환자가 다시 해석해야 하는 결합이 남지 않았는가
- 한 문장에 여러 행동이 들어가더라도 같은 진료 흐름으로 한 번에 이해되며, 주체나 시점이 바뀌는 곳에서는 문장을 나눴는가
- 직접 요청문이나 제3자 진료 설명에서 누가 움직이고 누가 묻거나 보는지 분명한가
- `그런데·그래서·다시·따로·이어`마다 앞 문장에 실제 대조·원인·반복·분리가 있으며, 지워도 뜻이 같으면 삭제했는가
- 질문과 지시만 이어지지 않고 환자의 장면, 질문의 이유, 원장의 판단이 섞여 자연스러운 설명 호흡을 만드는가
- v1.13 승인 원고처럼 문장·쉼표·문단 개수를 맞추지 않으면서도 한 번에 뜻을 알아들을 수 있는가
- 번호 답마다 원인·생활 장면·문진·진찰·안전 기준·치료 판단을 이해에 필요한 만큼 충분히 설명했는가
- 같은 임상 행동을 되짚었다면 독자의 이해나 안전을 위한 역할이 있고 동일 문장 복사가 아닌가
- 마무리가 번호를 기계적으로 복창하지 않으면서 구체 증상과 다음 행동으로 자연스럽게 닫히는가
- 마무리 소제목과 산문에 판단·선택·회복·출발·첫걸음 같은 표어가 없고, 불편이 계속되는 조건과 다음 진료 행동을 직접 말했는가
- 답 선공개가 쉼표 목록이 아니며 질문 절차·치료 행정을 판단 이유처럼 쓰지 않았는가
- 첫 진료·치료 직후·다음 날·다음 방문의 시간축이 논리적으로 이어지고, 결과지·사진에 붙인 동사가 실제 행동과 맞는가
- 모든 문장의 실제 주어·목적어·서술어·평이한 뜻과 문맥 속 역할을 설명할 수 있는가

이 검사가 통과해도 완성으로 표시하지 않는다. 다음 단계에서는 이 문서와 금지 패턴, 검색어 목록, 검사 결과, SEO 수치, 레퍼런스 문장을 모두 치우고 제목과 최종 평문만 새로 읽는다. 실제 원장 발화로 어색한 문장이 있으면 구조부터 고친 뒤 수정본 전체를 다시 읽고, 고칠 곳이 없으면 `no-change-needed`로 남긴다. 이어 최종 모든 문장을 하나씩 떼어 실제 주어·목적어·서술어·평이한 뜻을 기록하고 수 일치와 조사·병렬 구조까지 반대로 의심해 본다. 검사어를 다른 단어로 바꾸거나 검사 기록만 추가하는 것은 수정으로 인정하지 않는다.

내부 `speech-draft.json`의 각 case에는 다음 형태로 남긴다. `beforeBody`와 `finalBody`는 같은 수의 전체 문단이며, 실제로 달라진 문단만 `revisions`에 정확히 기록한다.

```json
{
  "title": "확정 제목",
  "finalBody": ["최종 1번 문단", "최종 2번 문단"],
  "writingVoiceReview": {
    "contractId": "writing-voice-final-rehear-v1",
    "skillName": "writing-voice",
    "stage": "after-complete-visible-prose-and-seo-before-production-assembly",
    "beforeTitle": "확정 제목",
    "beforeBody": ["검수 전 1번 문단", "최종 2번 문단"],
    "decision": "revised",
    "reviewChecks": {
      "wholeDraftReadAtSpeakingSpeed": true,
      "openingHookSetReheardTogether": true,
      "genericConnectiveTissueReviewed": true,
      "flattenedRhythmReviewed": true,
      "attentionAllocationReviewed": true,
      "unsupportedPolishReviewed": true,
      "distinctiveGrainPreserved": true,
      "directSubjectActionPurposeReviewed": true,
      "vagueNounWrappersReviewed": true,
      "softenedOrAbstractConclusionReviewed": true,
      "userApprovedDirectVoiceExamplesApplied": true,
      "directVoiceSentenceAuditCrossChecked": true,
      "wholeDraftReheardAfterEdits": true
    },
    "frozenMaterial": {
      "contentAndOrderPreserved": true,
      "factsAndMedicalBoundariesPreserved": true,
      "claimStrengthPreserved": true,
      "referenceMechanismsPreserved": true,
      "keywordAndTitlePromisePreserved": true,
      "htmlComponentsAndLinksPreserved": true
    },
    "revisions": [
      {
        "paragraphIndex": 1,
        "before": "검수 전 1번 문단",
        "after": "최종 1번 문단",
        "expressiveJob": "환자가 어느 동작에서 아픈지 바로 떠올리도록 추상 표현을 직접적인 말로 바꿈"
      }
    ],
    "finalStatus": "pass"
  }
}
```

수정이 없다면 `beforeBody`와 `finalBody`를 같게 두고 `decision`은 `no-change-needed`, `revisions`는 빈 배열로 둔다.

검수 기록은 `assets/writing-voice-final-review-contract.json`을 따르고 `scripts/validate_final_voice_review.py`로 기록의 완결성을 확인한다. 이 검사는 체크박스와 수정 이력을 검증할 뿐 산문의 자연스러움을 대신 판정하지 않는다. 같은 `speech-draft.json`을 반드시 `scripts/validate_natural_speech_suite.py`와 `scripts/validate_goldhand_voice.py`에도 통과시켜 질문 순서·질문 틀 반복·추상 연결 문장을 실제 문장 기준으로 막는다. 세 검사가 모두 통과한 글에만 `data-writing-voice-review="writing-voice-final-rehear-v1"`과 `data-writing-voice-status="pass"`를 표시한다. 이 속성은 제작 검수용이며 네이버 복사 본문에서는 제거한다.
