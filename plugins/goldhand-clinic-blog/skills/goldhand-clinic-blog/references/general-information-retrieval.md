# 일반 정보 다중 수집과 네이버 보충 검색

이 문서는 사용자가 직접 정한 주제·메인키워드·제목을 그대로 받아, 기존 금손 글 구조를 바꾸지 않고 본문에 필요한 일반 정보만 확보하는 절차다. 콘텐츠 정보 출처와 편집 마스터를 분리한다.

## 변하지 않는 것

- 인터뷰는 `글 주제 → 메인키워드 → 제목 5개 추천 → 추천 번호 선택 또는 제목 직접 입력` 순서다.
- 도입 질문, 고정 인사, 해결 방향 예고, 금손한의원 소개표, 정보 본문, 마무리, 이미지, 운영정보의 기존 순서와 HTML 계약은 바꾸지 않는다.
- 편집 구조·제목 장치·도입 설득·전환·마무리 감정은 `select_reference_master.py`가 고른 편집 마스터 한 편만 담당한다.
- 제목이 `2가지`를 약속하면 기존 본문 안에서 실제 답을 정확히 `1.`과 `2.` 두 개로 쓴다. 답 개수를 맞춘다는 이유로 새로운 카드나 섹션 구조를 만들지 않는다.

## 정보 수집 순서

1. 주제·메인키워드가 모여도 제목 확정 전에는 정보 수집을 시작하지 않는다. 먼저 `title-recommendation-contract.json`만으로 제목 5개를 제시하고 사용자의 선택을 기다린다.
2. 제목이 확정되면 그때 처음 `select_general_information.py`를 실행한다. 주제와 확정 제목의 실제 질문, 숫자 답 개수를 함께 전달한다.
3. `assets/wipark-content-briefs.json`과 `assets/user-general-information-references.json`에서 질환·증상 주제어가 실제로 맞는 글을 모두 찾는다. `원인`, `치료`, `2가지` 같은 공통 제목 표현만 맞는 글은 제외한다.
4. 관련 글 여러 편의 `generalInformationAtoms`를 합치고 의미가 같은 정보는 하나로 묶는다. 출처가 여러 개인 원자는 `sourceIds`를 모두 보존한다.
5. 제목이 요구한 답을 저장 원자만으로 직접 채울 수 있는지 검토한다. 단순 원자 수가 많아도 제목 질문과 관계없는 정보라면 부족한 것으로 본다.
6. 부족하면 `search_naver_background.py`로 한국어 네이버 검색을 한다. 메인키워드는 SEO용이므로 정보 검색어에서 제외한다. 검색은 Windows와 macOS 모두 브라우저 창·브라우저 로그인·사용자 화면 상태에 의존하지 않는 HTTP 방식으로 실행한다.
7. 네이버 결과의 후보 글은 `fetch_naver_post_text.py`로 임시 읽기만 한다. 서로 다른 발행자 2곳 이상의 정보를 비교하고, 치료·검사·중단·주의·응급 경계가 들어가면 한국 공식 의료기관 자료를 하나 이상 포함한다.
8. 읽은 문장에서 `증상·원인·생활관리·검사·치료의 일반 원리`만 짧은 정보 원자로 다시 적는다. 원문 문장을 초안에 전달하거나 어미만 바꿔 쓰지 않는다.
9. 검색 결과가 없거나 HTTP 방식이 막히면 현재 작업에서 사용할 수 있는 시스템 웹 검색으로 같은 한국어 검색어를 실행할 수 있다. 이 경로도 브라우저 GUI·로그인을 요구하지 않는다. 두 경로 모두 실패하면 사실을 만들지 말고 정보 수집 실패를 정확히 알린다.

## 다른 한의원 정보 완전 차단

각 출처에서 다음 항목은 일반 정보가 아니므로 모두 버린다.

- 한의원명, 원장명, 지역, 주소, 전화, 예약·상담 문구
- 원장 경력, 진료 건수, 환자 수, 후기·성과·만족도·치료 결과
- 특정 한의원의 진단법, 프로그램, 패키지, 장비, 처방 구성, 가격
- 특정 환자의 사례·경과·기간·전후 결과
- 출처의 사진·캡션·연락처·내원 유도

출처마다 업체명·인명·지역을 `blockedEntities`에 기록한다. 초안 뒤 `validate_information_sources.py --input content-sources.json --article article.html --json`을 실행해 동적 차단어가 본문에 한 번도 없는지 검사한다. 금손한의원과 박준희 원장에 관한 문장은 오직 `references/clinic-facts.md`의 확인된 사실만 쓴다.

## 작업 기록

한 글마다 내부 `content-sources.json`에 아래를 남긴다.

- 확정 주제·제목·메인키워드와 `structureContract=existing-goldhand-structure-unchanged`
- 사용한 저장·웹 출처, 발행자, URL, 출처별 차단 엔터티
- 중복 제거한 일반 정보 원자와 각 원자의 `sourceIds`
- 네이버 검색 사용 여부, 한국어 검색어, GUI·로그인 비사용 상태
- 제목의 숫자 약속과 실제 번호 답 개수
- 글에 삽입한 금손 사실과 `source=references/clinic-facts.md`

웹에서 이번 글을 위해 찾은 자료는 임시 작업 자료이며 자동으로 영구 라이브러리에 넣지 않는다. 사용자가 새 레퍼런스 글을 제공하면 출처 업체 정보를 분리·검토한 뒤 `user-general-information-references.json`에 일반 정보 원자만 추가하고 `validate_general_information_library.py`를 통과시킨다.
