# 제목의 질문에 답하는 원고

제목 확정 뒤 자료 선택보다 먼저 제목을 읽는다. 제목의 대상, 조건, 독자가 알고 싶은 점, 답의 종류, 서로 다른 답 개수를 내부 메모로 정한다. 제목을 읽은 뒤 사용자 핵심 내용 인터뷰 답변을 기다린다. 사용자가 중요하게 생각하는 내용을 번호 답의 중심으로 놓고 확정 제목에 맞게 설명하는 자료만 사용한다. 제목과 사용자 내용의 의미가 직접 충돌하면 해당 두 내용만 확인하고 임의로 사용자 내용을 바꾸지 않는다. 이 메모는 독립 편집자에게 전달하지 않는다.

각 번호 소제목에는 제목의 질문에 대한 직접 답이 하나씩 있어야 한다. `이유`는 원인, `방법·습관`은 행동, `신호·차이·확인`은 판별점에 답한다. 제목에 여러 조건이 있으면 한 조건을 생략하지 않는다. 본문의 설명은 그 답의 근거·이해에 필요한 예시·관련 안전 안내여야 한다. 다른 질환 설명으로 넘어간 문단은 제목과의 관계를 억지로 붙이지 말고 삭제하거나 다시 쓴다.

번호마다 답을 한 문장으로 압축해 나란히 비교한다. 두 문장이 사실상 같은 원인을 되풀이한다면 답 하나다. 이유 하나와 대처법 하나도 이유 두 개가 아니다. 확정된 제목을 바꾸거나 숫자를 낮추지 않는다. 사용자 항목이 부족·중복되면 필요한 내용만 확인하고, 항목 자체가 아닌 설명 정보만 부족하면 관련 자료를 보충한다. 주제와 맞지 않는 사진을 쓰기 위해 본문을 바꾸지 않는다.

## 독립 검수와 최종 문장 연결

초안과 다른 편집자가 **확정 제목과 최종 평문만** 읽는다. 일반적인 검수 프로토콜은 줄 수 있지만 작성자의 답 메모, 자료 목록, 예상 정답, 기계 검사 결과를 주지 않는다. 생활어 편집과 제목 논리 검수는 같은 독립 편집자가 하되 두 판단을 각각 기록한다.

독립 편집자는 다음을 실제 문장에 근거하여 확인한다.

1. 제목의 대상과 모든 조건이 본문에서 다뤄지는가?
2. 각 번호 답의 핵심 문장이 제목 질문에 바로 답하는가?
3. 답의 종류와 개수가 제목과 같고, 답끼리 의미상 다른가?
4. 질문·예고·본문의 모든 문단·정리·CTA가 같은 질문을 중심으로 이어지는가?
5. 사례나 특정 부위 설명이 주제를 대신하지 않는가? 안전 안내가 필요해도 새로운 고정 섹션을 만들지 않았는가?

위 독립 판단 뒤에는 [topic-priority-interview.md](topic-priority-interview.md)에 따라 사용자 원문을 추가로 받아 핵심 내용 중심 여부를 별도로 검수하고 `userPriorityReview`에 기록한다.

실패 부분은 작성자에게 구체적으로 돌려보내 자료와 본문을 바로잡는다. 수정된 평문 전체를 다시 검수하며 사용자의 중간 승인을 묻지 않는다.

`validate_title_alignment.py --input article.txt --title "확정 제목" --describe`는 현재 문장 해시와 **미검수** 틀을 제공한다. 편집자는 이 틀에 실제 판단을 채워 `independent-review.json`의 `titleAlignment` 객체로 기록한다. 별도의 `title-alignment.json`에 동일 객체를 저장해도 된다.

필드:

- `schemaVersion: 1`, `contractId: goldhand-title-answer-alignment-v1`
- `title`: 확정 제목 그대로, `bodySha256`: describe가 계산한 최종 평문 해시
- `draftAuthor`, `reviewer`: 실제 서로 다른 작성자와 편집자 식별값
- `reviewerInputMode: title-and-final-plain-text-only`
- `titleSubject`, `titleQuestion`: 제목의 대상과 독자의 구체 질문
- `answerType`: `reason`, `action`, `check`, `explanation` 중 describe가 알려 주는 종류
- `premiseCheck`: 제목의 조건 각각을 본문이 어떻게 다루는지 30자 이상 구체 설명
- `wholeBodyCheck`: 번호 밖 문단을 포함해 글 전체의 관련성을 확인한 50자 이상 설명
- `distinctionCheck`: 각 답의 차이를 30자 이상 설명
- `answers`: 번호 순서대로 `number`, 실제 `heading`, 해당 번호 설명의 `directAnswerExcerpt`, 제목에 답하는 이유인 `whyThisAnswersTitle`(30자 이상)
- `offTopicPassages`: 남은 관련 없는 구절 목록. 비어 있지 않으면 제작 불가
- `verdict`: 검수 전 `pending`, 수정 필요 시 `fail`, 실제 검수 완료 후 `pass`

글자 수는 원고 분량이나 SEO 기준이 아니라 빈 검수·체크박스를 막는 최소 기록량이다. 검사 통과가 의미 판단을 대신하지 않는다. 관련 없는 원고에 그럴듯한 검수 설명을 만들어 붙이는 것은 금지한다.

검수 뒤 최종 평문을 HTML로 옮기고 다음과 같이 결합한다. 인용구의 `>` 표시와 고정 소개 표, 표시용 줄바꿈을 제외한 문장·구두점·순서는 그대로여야 한다.

```bash
python3 scripts/validate_title_alignment.py --input article.txt --title "확정 제목" --review independent-review.json --json
python3 scripts/validate_title_alignment.py --input article.html --title "확정 제목" --review independent-review.json --html --attach-output article.html --json
```

결합된 기록은 `article`의 비표시 속성에 보존되고 네이버 복사 시에는 내부 속성과 함께 제거된다. 최종 원고 검사·복사 페이지 제작·복사 페이지 검사에서 누락 또는 본문 변경을 차단한다. 제목이나 본문이 바뀌면 기존 기록의 해시만 고치지 말고 독립 편집자가 다시 읽은 기록을 만들고 결합한다.

사진·색상·강조·줄바꿈만 바꿔도 되는 제작 단계에서 본문 논리가 달라질 수 없다. 사진 수는 자유지만 같은 원본은 한 글에서 한 번만 쓴다. 원본 ID, 파일 해시, 원본 주소를 변형본에도 보존하고 최종 HTML 전체를 검사한다.
