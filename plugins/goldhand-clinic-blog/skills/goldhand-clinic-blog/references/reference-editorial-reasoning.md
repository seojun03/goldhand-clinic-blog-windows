# 레퍼런스 편집 판단

이 문서는 선택한 위석 글의 문장을 흉내 내는 방법이 아니라, 그 글이 독자를 움직이는 이유를 금손한의원 글에 옮기는 방법을 설명한다. 모든 자동 작성에서 초안 전에 읽는다.

기계적인 구조 복사와 금손 말투 덮어쓰기를 차례로 하지 않는다. 먼저 선택한 한 편의 읽기 경험을 해석하고, 그 다음 각 기능을 금손 사실과 주제에 맞춰 다시 설계한다.

## 집필 전 편집 판단 카드

`assets/reference-writing-intelligence.json`에서 선택한 `masterId` 프로필 하나만 읽고 다음을 내부적으로 결정한다.

1. 이 글을 찾는 독자는 지금 어떤 불편·불안·의심을 갖고 있는가?
2. 원문 제목은 무엇으로 시선을 잡는가? 숫자, 권위, 대비, 지식 공백, 생활 장면, 결과의 모순 가운데 무엇이며 왜 효과적인가?
3. 원문 도입은 독자의 읽기 부담을 어떻게 낮추거나 궁금증을 어떻게 키우는가?
4. 독자가 계속 읽으면 얻게 될 보상은 이 주제에서 정확히 무엇인가?
5. 정보는 왜 그 순서로 공개되는가? 앞 문단이 다음 문단을 필요하게 만드는 연결을 적는다.
6. 경력·환자 수·원장 수·사례·프로그램 같은 원문 사실 슬롯은 어떤 신뢰 기능을 맡는가?
7. 같은 기능을 맡을 확인된 금손 사실이 있는가? 없으면 무엇으로 신뢰를 만들고 그 사실을 생략할 것인가?
8. 마지막에는 독자가 어떤 감정으로 이동해야 하는가? 안도, 현실감, 통제감, 희망, 감사 가운데 주제와 맞는 것을 고른다.

이 판단 카드는 제목 확정 뒤에 만들며 완성 본문에 노출하지 않는다. 선택 결과의 `referenceWritingIntelligence`와 `adaptationDecisionRequired=true`를 근거로 확정 제목의 심리 장치를 해석하고 도입·전개·마무리에 반영한다.

## `3분`을 해석하는 방식

`3분`은 모든 글에 붙이는 고정 문장이 아니다. 무릎 레퍼런스에서 이 숫자가 맡은 기능은 다음과 같다.

`구체적인 숫자 → 읽기 비용이 직관적으로 보임 → 짧다는 느낌으로 부담 감소 → 주의 확보 → 무릎 통증에서 얻을 구체적 실마리 약속`

여름 보약 레퍼런스는 같은 기능에 `2분`을 사용한다. 따라서 집필자는 다음처럼 판단한다.

- 글의 실제 밀도와 약속할 답을 먼저 본다.
- 분 단위 안내가 효과적인 주제인지 판단한다.
- 사용한다면 1~5분 안에서 실제 분량에 맞는 숫자를 고른다.
- 숫자 바로 뒤에는 그 글에서만 성립하는 보상을 붙인다.
- 시간 안내가 어울리지 않으면 대비, 긴급 경계, 결과의 모순, 생활 손실 같은 선택 프로필의 다른 장치를 쓴다.

`몇 분만 읽어 보세요` 뒤에 `도움이 될 겁니다`만 쓰면 실패다. `계단 통증에서 무릎 외에 무엇을 함께 볼지`, `얼굴 마비 때 응급 평가가 먼저인 신호`, `여름 보약 시기를 나눌 몸 상태`처럼 제목과 독자 고민에 직접 연결되는 보상이 필요하다.

## 제목을 해석하는 방식

제목의 숫자는 한 종류가 아니다.

- `2가지`, `3가지`: 본문 답의 수를 미리 보여 주어 정보량을 예측하게 한다.
- 경력 연수·환자 수·원장 수: 답변자를 믿을 근거와 경험의 폭을 암시한다.
- `vs`: 독자가 자신이 어느 쪽인지 대입하게 한다.
- `모르면 어렵다`: 놓친 지식이 있을 수 있다는 공백을 만든다.
- `같이 노력해도 결과가 다르다`: 모순으로 궁금증을 만든다.

원문의 숫자나 권위 사실은 옮기지 않는다. 같은 기능을 맡을 확인된 금손 사실만 쓴다. 현재 제목에서 사용할 수 있는 경력은 `11년차`이며, 원장 경력에만 연결한다. 환자 수·성과·지역 순위는 만들지 않는다.

글 주제와 메인키워드가 정해지면 편집 프로필이나 레퍼런스를 읽기 전에 `title-recommendation-contract.json`만으로 서로 다른 후보 5개를 만든다. 모든 후보는 정확 메인키워드로 시작하고 공백 제외 30자 이내다. `최악의·반드시·망치는·놓치면 손해·경고하는`처럼 독자가 바로 이해하는 강한 표현으로 얻을 이득 또는 피할 손해를 드러낸다. `나쁜·안 좋은·좋지 않은`처럼 약한 표현으로 바꾸지 않는다. 강한 표현은 습관·행동·신호·실수에 붙이고 치료 결과 보장, 공포 과장, 타 기관 비방에는 붙이지 않는다.

각 후보는 `11년차` 또는 `1가지·2가지·3가지` 중 하나 이상을 활용한다. 다섯 개 가운데 `11년차` 후보는 최소 1개, 1~3가지 후보는 최소 3개다. `workflowStage=title-first`로 `validate_title_recommendations.py`를 통과시킨 뒤 사용자에게 번호 선택 또는 직접 입력을 요청한다. 이 빠른 단계에는 `referenceMasterId`와 `titleMechanismId`를 넣지 않는다. 제목이 확정된 뒤에만 관련 정보를 수집하고 편집 마스터를 고른다. 숫자 답을 약속한 제목은 같은 수의 실제 답을 확보해야 하며, 확정 제목을 `validate_title.py --editorial-close --reference-master-id ... --title-mechanism-id ...`로 다시 검사한다. 숫자 약속은 리서치에서 확보한 실제 답 수를 `--answer-count`로 전달한다. 답이 부족하면 제목을 몰래 고치지 않고 새 제목 선택을 요청한다.

## 흐름을 옮기는 방식

`orderedContentAtoms`는 사실과 정보 순서를 지키는 골격이다. `referenceWritingIntelligence.flowBeats`는 독자가 왜 다음 문단을 읽게 되는지 설명하는 편집 흐름이다. 둘을 함께 사용한다.

각 흐름 비트마다 다음 세 줄을 내부적으로 만든다.

- 원문 기능: 독자의 어떤 질문이나 감정을 처리하는가?
- 금손 내용: 어떤 내용 원자와 금손 사실이 이 기능을 맡는가?
- 전환: 다음 내용이 왜 지금 필요해지는가?

이 과정을 거치면 같은 네 개의 내용 원자를 사용해도 글마다 도입과 전환, 강조 지점, 결론이 달라진다. 여러 레퍼런스를 평균 내거나 다른 글의 멋있는 문장을 끼우지 않는다.

## 디테일한 표현을 배우는 방식

완성 문장 대신 `microExpressionPatterns`의 기능과 모양을 사용한다.

- 독자의 반론을 먼저 인정하면 광고 경계가 낮아진다.
- 한 동작을 구체적으로 보여 주면 독자가 자기 증상에 대입한다.
- 결론을 먼저 말하고 이유와 예외를 설명하면 급한 질문에 빨리 답할 수 있다.
- 두 반대 선택을 나란히 놓으면 독자의 선택 피로를 줄인다.
- 정상에 가까운 검사와 실제 통증의 간극을 붙이면 궁금증이 생긴다.
- 본문의 답을 실제 명사로 다시 묶으면 기억하기 쉽다.

그 다음 금손 공식 말투로 자연화한다. 금손 말투 프로필은 위 기능을 지우지 않는다. 문장을 환자가 바로 떠올릴 생활어로 바꾸고, 박준희 원장이 실제로 말하지 않을 작문체만 걷어낸다.

`걸을 때 남는 통증`처럼 뜻은 통하지만 장면이 흐린 표현은 `계단을 내려갈 때 무릎 앞쪽이 다시 아픕니다`처럼 바꾼다. 단어 하나만 치환하지 말고 누가, 언제, 어떤 동작을 할 때, 어디가 어떻게 불편한지가 보이도록 문장 구조를 다시 쓴다.

## 마무리를 옮기는 방식

모든 글을 `사람마다 다르니 진찰이 필요합니다`로 끝내지 않는다. 선택 프로필의 `closingMechanism`에 따라 다음을 조합한다.

1. 본문의 직접 답을 실제 명사로 다시 묶는다.
2. 확인된 금손 경력이나 진료 태도가 주제와 맞으면 짧게 회수한다.
3. 독자가 가져갈 다음 판단 또는 안전 경계를 남긴다.
4. 레퍼런스가 감사로 닫히고 주제에도 자연스러우면 짧게 감사한다.

완성 HTML의 마무리는 아래 네 기능을 순서대로 모두 갖춘다.

1. 제목·증상·본문 결론과 맞닿은 짧은 소제목을 새로 쓴다.
2. 소제목 바로 뒤에 네이버 순정 구분선을 둔다.
3. 제목이 약속한 답과 본문에서 설명한 핵심을 실제 생활 장면으로 다시 묶는다.
4. 불편이 계속될 때 현재 상태를 함께 살펴볼 수 있다는 부담 없는 진료 안내로 닫는다.

위석 구안와사 글의 `25년 경험이 전하는 한 가지`는 이 구조를 확인한 레퍼런스 문구일 뿐 금손의 고정 제목이 아니다. 경력 숫자, `한 가지`, `오늘의 결론`, `마무리`를 공식처럼 반복하지 않는다. 글마다 독자가 마지막에 기억해야 할 증상·동작·치료 판단을 소제목으로 만든다. 진료 안내도 `지금 바로 예약`, `꼭 내원`처럼 재촉하지 않고, 어느 불편이 계속될 때 무엇을 함께 볼지 말한다.

무릎 글이라면 `걷는 모습`과 `발목·골반을 포함한 연결된 움직임`을 다시 말할 수 있다. 트라우마 글이라면 `몸의 반응`과 `마음의 안전한 속도`를 묶고 희망과 안전 경계를 함께 남긴다. 보험 글이라면 최신 일반 기준과 개인의 치료 적합성을 분리해 닫는다.

## 다른 사용자에게 이어지는 학습

이 시스템은 모델 자체를 자동 재학습시키지 않는다. 사용자가 명확히 승인한 편집 교훈만 `approvedLessons`에 넣고 플러그인 버전에 포함한다. 그러면 새 작업과 다른 사용자의 설치본에서도 같은 판단 구조를 읽을 수 있다.

생성된 모든 원고를 자동으로 학습 자료에 넣지 않는다. 잘못된 초안이나 일회성 취향이 공용 규칙으로 굳는 것을 막기 위해 다음 절차를 따른다.

1. 사용자가 표현이나 판단 원리를 명확히 승인한다.
2. 한 문장 예시가 아니라 재사용 가능한 심리·편집 원리로 정리한다.
3. 적용 조건과 실패 조건을 함께 적는다.
4. `validate_reference_learning.py`를 통과시킨다.
5. 플러그인을 새 버전으로 배포한다.

## 복사 경계

- 원문 업체 사실, 경력, 환자 수, 원장 수, 사례, 성과, 고유 치료·프로그램, 사진, 연락처는 금손 글의 사실이 아니다.
- 원문 완성 문장과 7어절 이상 연속 표현은 사용하지 않는다.
- 제목 장치, 독자 심리, 질문 기능, 정보 공개 순서, 전환 논리, 마무리 감정은 분석해 옮길 수 있다.
- 흔한 자연어까지 억지로 비틀지 않되, 원문 고유 문장 배열은 `validate_copy_overlap.py`로 차단한다.
