# 제목 확정 뒤 사용자 핵심 내용 인터뷰

추천 제목을 선택하거나 제목을 직접 입력하면 글을 쓰기 전에 다음 질문을 하고 답변을 기다린다.

`'{topic}'에 대해 중요하게 생각하는 {N}가지가 무엇인가요?`

- `topic`은 사용자가 선택하거나 직접 입력한 주제 그대로다. 제목, 상세 주제, 저장 자료의 주제로 바꾸지 않는다. `다이어트`를 선택했다면 제목이 요요에 관한 것이어도 질문의 주제는 `다이어트`다.
- `N`은 확정 제목의 `N가지`에서 가져온다. `11년차`, `3분`, 나이, 추천 목록 번호를 답 개수로 사용하지 않는다. `두 가지` 같은 한글 수 표현도 읽되 제목 원문은 바꾸지 않는다.
- 제목에 답 개수가 없으면 숫자를 만들어 넣지 않고 `'{topic}'에 대해 중요하게 생각하는 내용은 무엇인가요?`라고 묻는다. 답변에서 서로 다른 핵심 내용의 개수를 정한다.
- 제목에 서로 다른 답 개수가 있으면 충돌하는 개수만 확인한다. 주제가 없는 직접 제목 입력은 주제를 추정하지 말고 주제만 먼저 확인한다.
- 예시 답이나 저장 자료의 결론을 먼저 제시하여 사용자의 답을 유도하지 않는다. 답변 전에는 본문용 자료 선택, 평문, HTML, 이미지 작업을 시작하지 않는다.
- 이미 같은 주제·제목에 대한 인터뷰 답변을 받았다면 다시 묻지 않는다. 다른 주제·제목의 답변은 자동 재사용하지 않는다.

## 답변 기록과 다음 단계

`scripts/topic_priority_interview.py --topic "선택한 주제" --title "확정 제목"`으로 질문과 개수를 확인한다. 도구는 질문을 출력할 뿐 사용자의 답을 대신 만들지 않는다.

답변을 받은 뒤 작업 폴더의 `user-priorities.json`에 아래 내용을 기록한다.

- `topic`, `title`: 사용자 확정 원문
- `userResponse`: 인터뷰 답변 전체 원문
- `priorities`: 답변에서 그대로 뽑은 서로 다른 핵심 내용 문자열 목록. 사용자가 제시한 순서를 보존한다. 설명을 새로 만들어 넣지 않는다.

`scripts/topic_priority_interview.py --topic "선택한 주제" --title "확정 제목" --input user-priorities.json`이 `ready-for-user-centered-draft`이면 작성을 시작한다. 항목 수가 제목과 다르거나 내용끼리 겹치면 부족한 내용 또는 선택할 내용만 짧게 확인한다. 자료에서 항목을 채우거나, 사용자의 항목을 삭제·분할·합쳐 개수를 맞추지 않는다. 제목과 답변의 의미가 직접 충돌할 때도 충돌한 두 내용만 확인한다. 이것은 평문 승인이나 제작 여부 질문이 아니다.

## 반드시 사용자 답변을 중심으로 작성

1. 사용자가 중요하게 생각하는 각 내용을 번호 소제목의 직접 답으로 연결한다. 사용자 핵심 내용 → 소제목의 주장 → 해당 설명 순서로 먼저 설계한다.
2. 저장 정보 박사와 외부 자료는 사용자 핵심 내용을 설명하는 데 필요한 일반 정보만 보충한다. 자료가 풍부한 다른 주제로 중심을 바꾸지 않는다. 사용자 답변은 검증 요청이 없는 한 독립 검색·반박·순화의 대상이 아니다.
3. 각 번호 소제목의 주된 설명과 예시를 해당 사용자 내용에 집중한다. 도입에 한 번 언급하고 본문은 기존 자료대로 쓰거나, 마지막에 덧붙이는 방식은 실패다.
4. 사용자 내용의 의미·강도·순서를 보존한다. 읽기 쉽게 표현할 수 있지만 임의로 삭제·약화·다른 항목으로 대체하지 않는다. 서로 다른 핵심 내용이 N개라면 번호 답도 N개다.
5. 공감 질문, 3분 예고, 정리도 이 핵심 내용으로 이어지게 쓴다. 기존 단일 구조, 고정 소개 표, 의료 경계, 중립적인 CTA는 유지한다.

## 검수

기존 생활어·제목 검수는 제목과 평문만 보고 독립적으로 수행한다. 그 판단을 마친 편집자에게 `user-priorities.json`을 추가로 전달하여 별도의 사용자 핵심 내용 검수를 한다. 초안 작성자의 자기평가나 예상 정답은 전달하지 않는다.

`independent-review.json`의 `userPriorityReview`에 아래 내용을 실제로 검수하여 기록한다.

- `topic`, `title`, `userResponse`, `priorities`: 현재 인터뷰 기록과 동일한 원문
- `bodySha256`: `validate_title_alignment.py --describe`가 계산한 현재 본문 해시
- `draftAuthor`, `reviewer`: 실제 서로 다른 작성자와 편집자 식별값
- `answers`: 사용자 항목 순서대로 `priority`(원문), `number`(소제목 번호), `bodyExcerpt`(그 번호의 실제 본문 문장), `whyCentral`(단순 언급이 아니라 그 항목이 설명의 중심인 이유)
- `unresolvedPriorities`: 빠지거나 의미·강도가 달라진 내용 목록. 남아 있으면 수정한다.
- `verdict`: 실제 검수 전 `pending`, 수정 필요 시 `fail`, 검수 완료 후 `pass`

다음 검사를 평문 동결 전과 HTML 완성 후에 실행한다.

```bash
python3 scripts/topic_priority_interview.py --topic "선택한 주제" --title "확정 제목" --input user-priorities.json --article article.txt --review independent-review.json
python3 scripts/topic_priority_interview.py --topic "선택한 주제" --title "확정 제목" --input user-priorities.json --article article.html --html --review independent-review.json
```

기계 검사는 인터뷰 누락, 개수 불일치, 다른 인터뷰 재사용, 없는 인용문, 검수 뒤 본문 변경을 막는다. 실제로 사용자 내용이 중심인지와 의미·강도가 보존되었는지는 편집자가 판단한다. 맞지 않는 원고에 통과 기록만 붙이지 않는다.

인터뷰 답변과 필요한 누락·충돌 확인이 끝나면 추가 평문 승인이나 이미지·HTML 진행 질문 없이 검수와 최종 제작까지 완료한다.
